# 呆萌价返现功能评审 H5

依据用户确认的简版《呆萌价返现优化 PRD V1.3》和“返现设计”文件夹制作。保留目录、说明、完整 PRD、原图网格和交互注释。

## 内容

- 完整 PRD：7章，按返现流程、发单识别、具体页面、状态、结算扣款、风险与验收整理。
- 全托管默认关闭；开启且发单包含完整“奖&津”时，10秒后补发指定话术。发单规则位于具体页面要求之前。
- 后端根据返现打款表及时更新App“我的订单”：未扣清为“返现-未扣款”，扣清后为“返现-已扣款”；佣金不足时用后续佣金继续抵扣。
- 25 张设计原图：用户端9张、代理端10张、运营后台6张。
- 三端按功能分组全部展开；小程序画面宽屏3列、较窄窗口2列、窄屏1列，后台画面整行展示。
- 每张原图下保留独立说明；支持长图滚动、原图放大、关联画面定位、关联 PRD 和当前页面链接复制。
- 保留设计原图；当前业务要求以V1.3说明为准。
- 用户详情、团队返现设置、后台活动列表及后台活动区间配置缺少独立设计图，在说明中标记并关联 PRD。

本网站用于评审阅读，不连接真实订单、审核、支付或账单接口。

V1.2：明确打款失败的申请保留历史及原因，不计为有效申请；用户重新填写订单号创建新申请，走正常校验与确认流程。旧失败支付任务不直接重试；打款中、结果未明、已打款等其他重复申请仍拦截。

## 构建和预览

使用 Python 标准库，无需安装项目依赖：

```sh
python3 scripts/build.py
python3 -m http.server 4180 --directory dist --bind 127.0.0.1
```

浏览器访问 `http://127.0.0.1:4180/`。发布时使用 `dist/` 全部内容。

生成脚本会校验25张原图完整覆盖、7章PRD完整读取；PRD正文在 `prd.html` 中维护，画面名称和功能说明在 `scripts/build.py` 中维护。原V1.2 DOCX保留为历史文档。
